## 3. 해결 구조 — 0~4단계 파이프라인

**화면** (가로 흐름도로 그리기)
`0 문맥화 → 1 질의 변환 → 2 검색·리랭크 → 3 생성 → 4 검증 → 4b 문장 단위 인용 확인` (+ 근거 부족 시 자동 수집 → 다시 2단계)

| 단계 | 하는 일 | 모델 |
|---|---|---|
| 0 문맥화 | 멀티턴 대화의 후속 질문을 독립 질문으로 | LLM(경량) |
| 1 질의 변환 | 한국어 질문 → 영어 검색어 3개 | LLM(경량) |
| 2 검색·리랭크 | 의미 검색 + 키워드 검색(BM25) 결합 → 리랭커 → 다양성 선택 | bge-m3, bge-reranker-v2-m3 (로컬) |
| 3 생성 | 근거만 사용, 문장마다 [n] 인용 | LLM |
| 4 검증 | 근거와 대조해 채점, 실패하면 재작성 | LLM |
| 4b 인용 확인 | 문장마다 인용한 근거와 대조, 숫자는 원문과 규칙 대조 | 리랭커 (LLM 없음) |

**대본**: 검색과 인용 확인은 로컬 모델이라 비용이 들지 않고, 판단만 LLM이 합니다. LLM은 설정 한 줄로 바꿀 수 있고, 지금은 로컬 Qwen3.6만 씁니다.

```python
# 후: 저장 글·LLM 근거는 그대로, 리랭커만 "논문 제목\n본문"을 본다

```

**이 업데이트에 묶인 개선과 결과**

| 개선 | 결과 |
|---|---|
| 하이브리드 검색(BM25 + 벡터, RRF) | 모든 설정에서 벡터만보다 우위 |
| 다양성 리랭킹(MMR, 논문당 2청크) | 다중 홉 recall@5 0.733 → 0.800 |
| 한국어 키워드 검색("HyDE의" → "hyde") | MRR 0.9485 → 0.9543 |
| 리랭커에 논문 제목 | MRR 0.9545 → 0.9700, 다중 홉 recall +0.01 |

**대본**: 논문 제목을 임베딩까지 넣으면 MRR은 더 오르지만 다중 홉 recall이 떨어져 보류했고, 리랭커에만 넣는 방식을 골랐습니다(그래프 왼쪽 vs 오른쪽). 좋아 보여도 다른 지표를 깎으면 넣지 않았습니다.

## 9. 업데이트 ② 자기 확장 — 근거가 없으면 찾아온다

**그림**: `charts/03_corpus_growth.png`

**화면** (흐름)
근거 부족 감지(리랭크 최고 점수 < 0.2 또는 "찾을 수 없다") → 원 논문 제목 추정 + arXiv 검색 → 관련도 0.3 이상 → PDF 전문 추가 → 다시 답변

**대표 코드 변화** — 수집한 논문이 무관한 질문의 근거를 흐리던 문제
```python
# 전
c.rerank_score = float(s)
# 후: 자동 수집 논문은 0.7배 → 기존 논문 우선 (+ 참고문헌·부록은 아예 넣지 않음)
c.rerank_score = float(s) * (settings.auto_rerank_weight if c.origin == "auto" else 1.0)
```

**결과**: 수집 논문이 끼어들어 생긴 recall 손해 −0.0085 → −0.0017, 원 논문 수집률 26% → 62%(제목 추정). 코퍼스 크기별 측정으로 예산 2,000청크 + 오래 안 쓴 논문 자동 정리

| 함의(NLI) 판정 | 방향 뒤집은 문장 45% 탐지(리랭커 11%)지만 맞게 바꿔 쓴 한국어 문장도 모순으로 봄 → 사람 판정 뒤 결정 |
| 다중 홉 보충 검색 | 294문항에서 좋아진 문항 0, 나빠진 1 |
| 수집 신호 규칙 변경 | 후보 규칙 모두 감지 손해 |

**대본**: 이번 업데이트의 절반은 '넣지 않은 것'입니다. 제안은 여러 개였지만, 같은 평가셋을 통과한 것만 기본값이 됐습니다. 실수도 있었습니다 — 프롬프트 예시에 평가 질문의 답(ViT·Whisper)을 넣었다가 측정이 부풀려질 걸 알아채고 바꿨습니다.

## 14. 업데이트 ⑦ 답변 품질 — 독립 판정이 찾은 약점을 고친다

**그림**: `charts/10_answer_quality.png`

**왜**: 기준 세트 50문항을 독립 판정(Claude 초안, 사람 검토 전)해 보니 LLM 자기 검증은 50/50 통과였지만, 실제로는
"근거가 있는데 거절"·"두 번째 논문이 근거에 없음"이 가장 큰 약점이었다. 이것을 5단계로 고쳤다.

**대표 코드 변화** (`rag/pipeline.py`, `rag/stages/stage2_rerank.py`) — 다중 홉 질문의 두 번째 논문이 근거 5개 밖으로 밀리던 문제
```python
# 전: 질문 전체로 한 번 검색 → 한 논문이 근거 자리를 독차지
reranked = rerank(question, candidates)[:5]
# 후: 하위 질문으로 나눠 검색하고, 하위 질문마다 가장 맞는 논문이 5개 안에 하나는 들어가게
sub_questions = s1.transform_query(question, mode="decompose")   # 가벼운 LLM 1회 (rag/pipeline.py)
reranked = ensure_sub_coverage(sub_questions, retrieved, reranked)  # 가장 많이 든 논문의 가장 낮은 청크와 교체
```

**이 업데이트에 묶인 것과 결과** (판정은 Claude 초안 — 사람 검토 뒤 다시 잼)

| 단계 | 넣은 것 | 결과 | 결정 |
|---|---|---|---|
| 1 | 생성 프롬프트 v2: 답할 수 있는 부분은 답하고 빠진 부분만 밝힘, 이어 낸 판단은 "(추론)" | 맞음 36 → **41**/50, 다중 홉 5 → 9/18, 퇴보 1 | 기본 |
| 2 | 검증 v2: 질문을 함께 주고 "근거에 있는데 빠뜨린 부분"까지 판정 | 판정 일치도 κ **0 → 0.675** (규칙 판정은 v2 답에서 0.299) | 기본 |
| 3 | 다중 홉 분해 + 하위 질문별 근거 자리 | 기대 논문 재현율 0.925 → **0.970**(67문항), 단일 227문항 변화 0, 다중 홉 맞음 9 → **11**/18 | 기본 |
| 4 | 인용 확인 오경보 줄이기(소제목·안내 문구 제외) | 오경보 22 → 5 | 적용 |
| 5 | 원 논문 수집 실전 재시험(25문항) | 원 논문 수집 10 → **11**/20, 근거 부족 답변 4 → 2, 같은 질문 재수집 1 → **0**, 무관한 질문 수집 0편 유지. 문항당 25 → 36초 | 목표 60%에 1문항 모자람 |

**사람 판정으로 확인 — 초안을 숨긴 10문항** (판정기가 엇갈린 5 + 모두 동의한 5)

| 판정기 | 사람의 '맞음' 여부와 일치 | κ |
|---|---|---|
| Claude 판정 | 5/10 | 0.00 |
| 검증 v2 | 5/10 | 0.07 |
| 규칙(거절 표현 없음) | 4/10 | −0.07 |
| 문장 인용 확인 | 사람이 짚은 14문장 중 0~2 | — |

- 사람은 "근거에 없다"고 밝힌 답은 맞음으로, 근거가 직접 말하지 않는 **관계·종합 문장**("A가 B를 바탕으로", "두 관점은 보완")이 섞이면 부분으로 봤다.
- 리랭커 기반 인용 확인은 주제가 같으면 통과시켜 이 종류를 못 잡는다 → 36 → 41 은 **Claude 판정 기준**으로만 말한다. 검색·수집 지표는 정답 논문으로 재므로 영향 없음.

## 18. 한계와 배운 점

**화면**
- 한계: 자동 판정(Claude·검증 v2·인용 확인)이 사람 판정과 잘 맞지 않음(초안 숨긴 10문항에서 맞음 여부 κ 0 안팎) — 답변 품질 수치는 Claude 판정 기준 / 관계·종합 주장을 잡는 판정기가 없음 / 원 논문 수집 55%(목표 60%) / 평가 질문 대부분이 코퍼스에서 만든 것 / 인용 확인은 관련도 모델이라 함의를 직접 판정하지 못함(NLI 는 한국어 바꿔 쓰기에 오경보) / 한 사람용
- 배운 점
  1. 작은 표본의 결론은 뒤집힌다 — 평가셋 확대가 가장 큰 개선
  2. 지표는 서로 부딪힌다 — MRR과 다중 홉 recall
  3. 같은 아이디어도 넣는 위치에 따라 득실이 다르다
  4. 자동 테스트는 내 컴퓨터에 숨은 의존성을 드러낸다
  5. 제안이 측정을 통과하지 못하는 일이 많다 — 넣지 않은 결정도 기록한다
  6. 평가 질문의 답이 프롬프트에 들어가면 측정이 부풀려진다
  7. 같은 시험도 숨은 설정(생각 켬/끔)이 다르면 비교가 안 된다 — 조건을 스크립트에 고정한다
  8. 답이 바뀌면 판정기도 다시 재야 한다
  9. 사람 판정은 초안을 숨기고 받아야 한다 — 초안이 보이는 화면에서 저장한 40문항은 모두 초안과 같았다 — 예전 답에서 좋던 규칙 판정(κ 0.722)이 새 답에서 0.299로 무너짐

## 갱신 방법

새 작업이 끝나면 슬라이드를 하나씩 늘리지 않고, 7장 표에 **업데이트 묶음**으로 한 줄 추가하거나 기존 묶음의 결과를 고친다.
수치가 바뀌면 17장(달성률)과 차트(`make_charts.py`)를 다시 만든다. 사람 판정 문항이 늘면 14장의 사람 판정 표(지금 10문항)를 갱신한다.

## 발표 전에 직접 준비할 것

- 3·9번 슬라이드의 흐름도(PPT 도형으로 그리기)
- 12번: "확인이 필요한 문장"을 펼친 캡처가 필요하면 챗봇에서 같은 질문 후 펼쳐서 캡처
- 코드는 Consolas 등 코드 글꼴 14pt 이상, 전/후를 좌우로 배치
