## 1. 해결하려는 문제

| 문제 | 판정 | 근거 |
|---|---|---|
| 논문이 너무 빨리 쌓인다 | ✅ | 논문 490편(2,436청크)과 자동 수집 25편을 질문 하나로 검색·요약. 질문당 약 1분(§5.9) |
| 일반 챗봇의 답은 확인하기 어렵다 | ✅ | 문장마다 `[n]` 인용, 4단계 검증과 재작성. faithfulness 0.953(Claude, hard 31, §5.7), 0.994(Qwen 자기 채점, hard 69, §5.9) |
| 언어 장벽 | ✅ | 한국어 질문을 영어 검색어로 바꾸고 다국어 임베딩(bge-m3)으로 검색. 평가셋 294문항 recall@5 0.9694 |
| 최신 논문은 모델이 모른다 | 🟡 | 근거가 없으면 arXiv에서 수집해 다시 답함(KAN 최고 점수 0.006→0.990, §5.14). 원 논문 수집은 수집이 일어난 질문의 64%(§5.17) |
| 자료를 외부로 보내기 어렵다 | ✅ | 로컬 Qwen3.6 + 로컬 Chroma로 전체 파이프라인 동작(§5.8). 단, 자동 수집을 켜면 검색어가 arXiv·OpenAlex로 나감 |

## 2. 접근 방식

| 접근 | 판정 | 근거 |
|---|---|---|
| 근거만 쓰고 인용, 검증 실패 시 재작성 | ✅ | 시나리오 시험의 모든 답변이 검증 통과(§5.19). 근거가 없으면 "찾을 수 없다"고 밝힘(§5.8) |
| 근거가 없으면 논문을 찾아 추가 | 🟡 | 동작은 확인(시나리오 판정 통과, 무관한 질문 추가 0편, 재수집 0회). 목표 미달 2개: 원 논문 수집 45%(목표 60%), 코퍼스 안 질문의 수집 신호 23%(목표 5%) (§5.17) |
| 질의 변환 + 의미·키워드 검색 + 리랭커 | ✅ | multi_query·하이브리드가 111문항에서 recall@5 0.968로 최고(§5.7). 다양성 리랭킹으로 다중 홉 recall 0.794→0.850(§5.6) |
| 감이 아니라 수치로 결정 | ✅ | 평가셋 294문항. 소표본으로 고른 HyDE를 확장 평가로 되돌림(ADR-001, §5.7) |
| LLM 백엔드 교체 가능, 로컬 실행 | ✅ | Claude·OpenAI·로컬 3종을 `rag/llm.py` 한 곳에서 교체. 벡터 DB도 Chroma·Pinecone 교체(§5.11) |

## 다음에 하면 달성률이 오르는 일

진행 방향은 A(신뢰성 마무리)와 C(연구 도구화)로 정했습니다(2026-11-12). 순서는 [PROGRESS_REPORT §6](PROGRESS_REPORT.md)을 보세요.

1. **원 논문 수집률 60%**: 오래되고 유명한 논문이 검색 결과 뒤로 밀리는 문제(이슈 14).
2. **수집 신호 5%**: 다중 홉 질문의 일부 근거 부족을 걸러 내는 문제(이슈 16).
3. **한국어 키워드 검색**: 형태소 분석 또는 bge-m3 sparse 출력. 변경 범위가 작아 단기 달성률을 바로 올림.
4. **실제 질문 평가셋**: 평가셋이 쉬울 수 있다는 한계를 직접 줄임.
